What the blockers became

RESOLVED The server computes now

Seventeen endpoints, nine of them computed rather than fetched: /projection, /search, /coverage, /changes, /indexing and the trail routes. Writes snapshot the state they replace, so a change has an identity and a trail can be compared against the model it was recorded against.

RESOLVED Eight of nine lenses have data

Behavior reads 108 outcome nodes extracted from declared responses. Tests reads 149 test files carrying 1,329 named scenarios. Why reads documents and decision records. History reads git. Journey reads 32 derived branching flows.

RESOLVED Trails exist

Persisted per-row with focus, lens, altitude, question, note and timestamp per step. Forkable, listable, and assessed for freshness against the current model on every read — a stale trail says which steps broke rather than replaying silently.

REMAINS Runtime needs a source

HAR and OpenTelemetry ingestion both work, and an operation returning a status its specification never declared is reported as a mismatch. But nothing in a repository says what happened when the code ran, so this lens stays empty until someone connects telemetry. It reports that honestly rather than rendering a blank panel.

REMAINS No identity, roles or ownership

The spec's team surfaces — five roles, domain ownership, shared and recommended trails — need authentication that does not exist. Trail visibility is modelled; nothing enforces it.

What is genuinely ready

Measured, not assumed — all of this runs against the real repository today.

  • Projection engine. Focus, altitude, lens and trail resolve to ranked entities with narrative, grounded questions, budgets, diversity selection and honest notices.
  • Extraction. OpenAPI with declared outcomes, file-level codebase, Go backend, transitive API linking, tests with scenario names, markdown and decision records, git history, and HAR/OTel runtime.
  • Evidence. Six of seven sources produce. Disagreement is surfaced per source rather than averaged, and human verification survives re-import.
  • Semantic change. Snapshots on write; changes report affected journeys, gained and lost failure branches, affected tests and possibly-stale docs.
  • Coverage and indexing. Eight dimensions per domain, and a twelve-stage pipeline report that distinguishes "found nothing" from "cannot run".
  • Trails. Persisted, forkable, freshness-assessed, and shareable through URL state that carries the path and not just the destination.

Known traps

  • Three backend importers are stubs. nodejs.ts, python.ts and rust.ts return unsupported_language in fourteen lines. The Node plugin declares .js .mjs .cjs .ts, so a JavaScript-dominant tree dispatches to a stub and silently yields nothing.
  • The dev server loads the API lazily through ssrLoadModule. Do not "simplify" it back to a direct import — Vite inlines the config's graph, where the @/ alias does not resolve, and it fails with an opaque error that names no file.
  • Name collision on "lens". src/schema/entity/lens.ts means entity-scoped subgraph filtering, unrelated to the spec's lenses. Worth resolving before UI work begins.
  • Health is declared and consumed nowhere. Dead field in types.ts.
  • The old 3D UI is still present. GraphExplorer.tsx and urlState.ts still run; both go when the new UI lands.
  • The code altitude is empty because extraction is file-level. Deliberately deferred after review: the pathology concentrates in a single file, and a regex symbol extractor misses exports in 47% of files.

What the UI still needs from us

Ordered by what blocks design decisions soonest.

  1. Decide the Runtime story

    The lens works but needs a HAR or OTel export. Designs need a genuine "no telemetry connected" state, since this cannot be filled from a repository.

  2. Author one real user journey

    Derived journeys describe single operations. A user goal like "deposit money" spans several operations and screens, and only a person can say where it starts and ends.

  3. Add identity if team surfaces are in scope

    Roles, domain ownership and shared trails all assume authentication that does not exist yet.

  4. Retire the old UI

    GraphExplorer.tsx and urlState.ts come out when the new interface replaces them.
