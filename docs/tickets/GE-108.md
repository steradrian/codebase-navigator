# GE-108 — Legend counts + click-to-filter-by-type

**Status:** DONE
**Phase:** UX
**Effort:** S
**Depends on:** — (complements GE-104 if shipped alongside)
**Blocks:** —

## Summary

Each entry in the bottom-left legend shows how many nodes of that type exist. Clicking an entry filters the graph to that type (via the same dim mechanism GE-104 uses). Shift-click for multi-select.

## Context

Today's legend is purely informational — dots and labels. At a glance you can't tell how big the graph actually is, or where weight sits ("23 UI, 40 API, 9 Database" is much more useful than "UI, API, Database"). And since users look at the legend while deciding what they want to see, turning it into a quick filter entry point reduces clicks.

## Scope

- Legend item layout becomes: `● Type label  [N]` — color dot, label, count pill.
- Count computed from the current schema's `nodes` array, memoized per schema update.
- Clicking a legend item toggles that type in the filter set. Visually highlights the active entries.
- Shift-click multi-selects additional types; plain click selects only the clicked type (clears others).
- A "Reset" control appears when any filter is active.
- When GE-106 (color-by-entity) is ACTIVE, the legend content swaps to list entities with counts. Same click-to-filter behavior — just on the entity facet.
- Visual dim behavior shares the same layer as GE-104's filter rail. If both the legend and filter rail are modifying the same facet, the rail wins (legend is a quick shortcut, not a source of truth).

## Out of scope

- Filter by entity / origin from the legend. Only type (or entity in color-by-entity mode). The filter rail covers the rest.
- Saved filter presets.
- Drag-to-reorder legend entries.

## Acceptance criteria

- Legend shows accurate counts for every type present.
- Counts update automatically after imports / edits.
- Clicking a legend type dims all non-matching nodes + edges.
- Shift-click adds to the filter set; plain click replaces.
- A Reset control appears when filter is active and restores everything.
- Works correctly in both type-color and entity-color modes.

## Risks

- Interaction with the filter rail (GE-104) needs a single source of truth for filter state. The legend's click is a write to the same state the rail renders.
- Count recomputation on every render would be wasteful. Memoize.

## Notes for the implementer

Use a `useMemo` keyed on `schema.nodes` for the counts. The click handler should be wired to the same filter state GE-104 owns. Keep the legend's styling updates tight — we're touching a surface that currently looks clean.
