# GE-106 — Color-by-entity rendering mode

**Status:** DONE
**Phase:** Visualization
**Effort:** S
**Depends on:** GE-103 (entity field)
**Blocks:** —

## Summary

Top-bar toggle that recolors every node by its `entity` field instead of by its `type` field. When active, the graph re-reads as a per-entity flow: every Customer node (UI / API / DB) shares one color, every Payment node another. The type information demotes to a subtle inner-dot indicator.

## Context

When users are telling an entity story ("walk me through the Payment flow"), type-coloring doesn't serve them — it's a technical layer that's not what they want to see. Entity-coloring turns the full-stack graph into a visual per-domain map at a glance.

Cheap to build once GE-103 exists. High visual impact for the demo.

## Scope

- Top-bar toggle button: `● Type` / `◐ Entity`. Two states only — monochrome isn't a mode.
- When entity mode is active:
  - Node sphere color is computed from a deterministic palette keyed by `entity` string (same hash-based palette used by `groupColor` in GE-011).
  - Nodes without an `entity` field render in a muted gray.
  - Glow halo opacity unchanged.
  - Inner 30% of the sphere gets a small inset dot using the node's type color — type info is still accessible, demoted in visual weight.
- When entity mode is active, the legend (bottom-left) swaps content to list entities instead of types, each with its hash-palette color and count. (GE-108 adds counts; this ticket uses whatever the legend structure is at implementation time.)
- Entity color also propagates to:
  - Group hulls — if a hull's group maps 1:1 to an entity (possible when groups and entities align), the hull uses the entity color.
  - Path highlight color — unchanged (paths have their own palette).
- URL state (GE-022) includes entity-mode flag.

## Out of scope

- User-customizable entity palette. The deterministic hash is "fine enough" and adding UI for color picking is overkill for MVP.
- Per-entity guided paths auto-generation. Post-MVP nice-to-have.
- Smooth color-transition animation when toggling (snap is fine for now).

## Acceptance criteria

- Toggle flips between type-color and entity-color modes with no hitch.
- Nodes without entity are visibly distinguishable (muted).
- Type dot remains readable on the entity-colored sphere.
- Legend swaps correctly.
- URL round-trips the mode.

## Risks

- Type's color palette and entity's hash palette will overlap in color values for some inputs. Test with a realistic schema — if type colors and entity colors collide on the same node class, tune one palette or both.
- The inner type-dot must not shrink too small to read at a distance. Scale with the outer sphere.

## Notes for the implementer

Reuse `groupColor` from GE-011 or a sibling `entityColor` with the same hash approach. Keep it a ref-read in the animation loop so the toggle is effectively free.
