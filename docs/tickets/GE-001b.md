# GE-001b — Enable TypeScript strict mode

**Status:** TODO
**Phase:** Scaffolding (follow-up to GE-001)
**Effort:** M
**Depends on:** GE-001
**Blocks:** —

## Summary

Flip `tsconfig.json` to `strict: true` (and progressively turn on `noImplicitAny`, `strictNullChecks`, etc.) once the codebase is stable enough to absorb the friction. Fix the errors that surface — mostly narrow union narrowing issues that forced defensive flattening during the MVP.

## Context

GE-001 intentionally shipped TypeScript with `strict: false` to avoid blocking the migration on every latent type issue. That compromise has produced two known consequences during the MVP:

- `ImportResult` (GE-010, `src/schema/io.ts`) was authored as a discriminated union `{ ok: true; schema } | { ok: false; message }` but TypeScript without strict flags failed to narrow `result.ok` properly in the consumer site. Flattened to `{ ok: boolean; schema: Schema | null; message: string | null }` as a workaround.
- `SuggestResult` (GE-017, `src/ai/describe.ts`) hit the same issue and was flattened the same way.

Enabling strict mode will:
- Restore discriminated-union narrowing so future similar types can be written cleanly.
- Surface latent nullability bugs that silently pass today.
- Enforce consistency at module boundaries where the MVP elided it.

## Scope

- Turn on the following one at a time, fix each pass before moving on:
  - `noImplicitAny: true`
  - `strictNullChecks: true`
  - `strict: true` (enables the rest)
  - `noUnusedLocals: true`, `noUnusedParameters: true`
- Restore `ImportResult` and `SuggestResult` to their original discriminated-union shapes; update consumers to use proper narrowing.
- Audit all refs and state for implicit `null` / `undefined` handling.
- `tsc --noEmit` passes cleanly after the flip.

## Out of scope

- Refactoring the shape of any type beyond the two known flattened results.
- Any runtime behavior change.

## Acceptance criteria

- `tsc --noEmit` passes with `strict: true`.
- `ImportResult` and `SuggestResult` are discriminated unions again.
- No new `any` or `// @ts-ignore` introduced. Any narrow-miss is fixed at the source.
- Existing test suite still passes.

## Risks

- Surprising number of cascading errors once `strictNullChecks` flips. Budget for an iterative fix cycle.
- Three.js's `@types/three` has some loose signatures — may need `as` at the boundary in a few places. Minimize and document each.

## Notes for the implementer

Turn on flags one at a time to keep the error set manageable. Start with `strictNullChecks` since that's where most of the value lives.
