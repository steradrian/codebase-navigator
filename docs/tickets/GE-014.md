# GE-014 — Impact analysis / blast radius

**Status:** DONE
**Phase:** Phase 2 — Intelligence
**Effort:** M
**Depends on:** GE-003
**Blocks:** —

## Summary

Select a node and see a red cascade spreading outward through its dependents, answering the question: "what breaks if this goes down?" A reverse mode answers: "what must be working for this to function?"

## Context

This is one of the two "aha" features of Phase 2 (alongside path authoring). Every engineer, SRE, and PM who looks at a system graph eventually asks "if I change this, what else am I on the hook for?" Most tools require reading the graph manually. This feature answers in one click.

The logic is simple graph traversal. The value is in the visualization and the thresholds — a naive flood fill makes everything red, which is useless. The implementation must weigh severity by hop count and link type so users can see the shape of the impact, not just its extent.

## Scope

- A mode triggered from the node's detail panel (button: "Show blast radius" or equivalent).
- **Downstream mode (default)**: traverse outgoing links from the selected node, marking every reachable node with a severity that decays with hop count and link type weight. Higher severity = redder and more opaque; nodes beyond a threshold fade to normal.
- **Upstream mode (toggle)**: traverse incoming links to show ancestors / dependencies.
- Link types influence severity: `dependency` links propagate severity more strongly than `data_flow` or `triggers`. Use the `weight` field from the v1.0 schema when present; fall back to sensible per-type defaults otherwise.
- The side panel lists affected nodes grouped by severity, sorted by distance from the selected node.
- Clicking an affected node in the list flies the camera to it and shows its own detail panel without exiting blast-radius mode.
- Exit blast-radius mode restores the normal selection view.
- The mode works on guided paths (answering "what does this path depend on?").

## Out of scope

- Probabilistic or conditional impact (what breaks X% of the time). Deterministic graph reachability only.
- Temporal impact (what breaks immediately vs. eventually). Out of scope for MVP.
- Multi-node selection (blast radius from a set of nodes). Single starting node only.
- Integration with real monitoring data — that is GE-028.

## Acceptance criteria

- From any node, the user can trigger downstream or upstream blast radius and see the graph colored accordingly within one frame or two.
- The side panel lists affected nodes in an order that reflects severity (closest and most-dependent first).
- Clicking an affected node navigates without losing blast-radius context.
- Exiting restores the previous view cleanly.
- The feature works on graphs up to 1,000 nodes without perceptible lag.
- Severity computation is deterministic and testable as a pure function.

## Risks

- Naive traversal on dense graphs lights up everything. Severity decay and threshold cutoffs are essential — tune against a real schema before closing.
- Upstream mode is conceptually different from downstream but users will expect symmetric behavior in the UI. Make the direction toggle clearly visible.
- Nodes already highlighted by selection or guided path must visually defer to blast-radius colors while the mode is active, or the user cannot read severity.

## Notes for the implementer

The traversal logic is a pure function — extract it from the UI and test it separately. The UI is straightforward once the data is right. Spend the design budget on the severity gradient and threshold — that is where the feature's usefulness lives.
