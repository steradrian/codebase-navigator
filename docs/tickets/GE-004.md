# GE-004 — Bugfix: Three.js scene rebuild on activePath change

**Status:** DONE
**Phase:** Scaffolding
**Effort:** S
**Depends on:** GE-001
**Blocks:** —

## Summary

The main `useEffect` in `GraphExplorer` that constructs the entire Three.js scene (scene, camera, renderer, meshes, sprites, lines, listeners) includes `activePath` in its dependency array. Every time a user enters or exits a guided path, the effect tears down the full WebGL context and rebuilds every node mesh, label sprite, and link line from scratch. This is invisible at 25 nodes but will become a visible freeze at 200+, and it compounds badly with every subsequent performance optimization.

## Context

Found during initial code review. Located at approximately `src/GraphExplorer.jsx:154–423` (the Three.js setup effect) and the dependency array at the effect's closing line that reads `[selectNode, clearSelection, activePath]`.

The `activePath` dependency was added because some visual logic inside the animation loop references `activePath?.color` for path highlighting. The fix is to read that value from a ref, the same pattern already used elsewhere in this component for `selectedRef`, `connectedRef`, and `pathHighlightRef`.

## Scope

- Remove `activePath` from the scene-setup `useEffect` dependency array.
- Introduce an `activePathRef` (or extend `pathHighlightRef` to carry the path color) so the animation loop can read the current path's visual state without the component re-mounting the scene.
- Confirm that entering and exiting paths updates visuals correctly without the scene being torn down.
- Confirm other behaviors that depended on the rebuild (if any) still work: path first-node camera focus, path highlight fade-in, and exit-path cleanup.

## Out of scope

- Any broader refactor of the giant `useEffect`. That is worth doing but belongs in a separate ticket after the MVP.
- Extracting scene setup into a hook or class.
- Changing the overall architecture of how Three.js state and React state communicate.

## Acceptance criteria

- Entering a path does not trigger a WebGL context recreation (verifiable via `console.count` on the effect body, or by observing that the node meshes retain the same object identity before and after path activation).
- Path highlight visuals still work: only path nodes are lit, only path links are colored with the path's color, annotation panel updates per step.
- Exiting a path restores the default view correctly.
- No regression in selection, search, or keyboard navigation.

## Risks

- The closure captured by `animate()` references `activePath` directly today. Missing one reference leaves stale visuals. A ref solves this but requires every read to go through `.current`.
- If the rebuild was accidentally serving as a cleanup mechanism for some subtle state, removing it could leave visuals in a wrong state on exit. Test exit-path carefully.

## Notes for the implementer

This is a one-line fix to the dep array, plus a handful of ref-read substitutions in the animation loop. Do not let it grow. If you notice other issues in the same effect — and you will — log them as follow-up tickets and stay focused on this one.
