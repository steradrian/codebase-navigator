# GE-012 — 2D toggle view

**Status:** DONE
**Phase:** Phase 1 — Foundation
**Effort:** M
**Depends on:** GE-003
**Blocks:** —

## Summary

A toggle that switches the graph between 3D force-directed layout and a 2D flat layout, preserving selection, search, and guided path state across the switch.

## Context

Some users cannot read 3D graphs (motion sensitivity, accessibility, cognitive preference). Some contexts demand 2D: screenshots in docs, slides, printed materials, embedded previews. A 2D view also projects better at low zoom and for quick-glance inspection.

The force simulation is already most of the way there — dropping the z-dimension is mechanical. The interesting work is preserving visual continuity when switching, so users do not feel disoriented.

## Scope

- A UI toggle (button, top bar) that flips the view between 3D and 2D.
- In 2D mode, the force simulation runs in two dimensions; node positions animate to their new flat positions rather than snapping.
- In 2D mode, the camera is orthographic or fixed-perspective looking down, with pan and zoom (no orbit).
- Labels always face the camera, links remain visible.
- Group hulls (GE-011) render as 2D polygons in 2D mode.
- Selection, search, and guided path state persists across the mode switch. Users should not lose their place.
- The toggle persists within the session.

## Out of scope

- Graph re-layout optimization specifically for 2D aesthetics (e.g., minimum edge-crossing algorithms). The force simulation's 2D projection is sufficient.
- Export to SVG or PNG in 2D mode. Defer to a post-MVP ticket.
- Printable layouts with axes, legends, titles.
- A third layout mode (timeline, radial, etc.).

## Acceptance criteria

- Toggle flips cleanly between 3D and 2D with an animated transition.
- All MVP interactions (select, search, guided paths) work identically in both modes.
- Framerate is stable in 2D mode.
- Labels remain legible at all zoom levels.

## Risks

- The existing simulation computes three velocity components. Zeroing the z-axis is easy but the camera, interaction handlers, and rendering code all assume 3D in various places. Expect to find a handful of subtle places where `nd.z` needs conditional handling.
- Animating between 3D and 2D positions is the part that is easy to get wrong — too abrupt feels jarring, too slow feels sluggish. Target ~500ms ease-out.

## Notes for the implementer

This is a lower-priority MVP feature — it is table stakes for accessibility and docs, but nobody will adopt the tool because of it. Keep scope tight. If something turns out hard, cut it to a follow-up rather than expanding the ticket.
