# GE-030 — Embeddable widget

**Status:** TODO
**Phase:** Phase 4 — Ecosystem
**Effort:** M
**Depends on:** GE-020, GE-022
**Blocks:** —

## Summary

Package the graph viewer as an embeddable widget — a `<script>` tag or iframe — that can be dropped into Notion, Confluence, internal wikis, and external documentation sites. Read-only mode by default, with optional interactivity.

## Context

Graph Explorer is most valuable when it shows up in the places people already look. Engineering docs in Notion, runbooks in Confluence, architecture decision records in GitHub — these are where the answer to "how does this work?" lives today. An embeddable widget means the graph appears there without forcing readers to open another tab.

This ticket turns the app into a platform primitive.

## Scope

- An embed endpoint that renders a simplified, read-only view of a graph. No editor, no importers — just the viewer, search, and guided paths.
- Two embed formats:
  - **Iframe** — drop-in URL that any HTML-embedding platform (Notion, Confluence, wikis) can consume.
  - **Script tag** — a small JS loader that mounts the widget into a designated div, for embed hosts that support arbitrary HTML/JS (docs sites, landing pages).
- URL parameters for initial view state — selected node, active path, camera position — reusing the encoding from GE-022.
- A configuration for embed permissions — public read, authenticated read, or private. Respects the auth model from GE-020.
- A responsive layout that works in narrow embed frames (as small as 400×300).
- A "view full" link that opens the full app with the same state.

## Out of scope

- Editing from within the embed. Viewer only.
- Theme customization beyond light / dark mode. Post-MVP.
- Deep customization of the embed's UI (hiding specific controls, etc.). Fixed layout for MVP.
- Analytics / view tracking of embed usage.

## Acceptance criteria

- An iframe embed works in Notion and Confluence (or the team's chosen wiki).
- A script-tag embed mounts correctly on a sample docs site.
- URL-encoded initial state is respected on load.
- The embed respects access permissions — private graphs show an auth prompt, public graphs load directly.
- The layout is usable at 400×300 minimum.
- The "view full" link preserves state across the transition.

## Risks

- Cross-origin concerns. iframes can be sandboxed aggressively by the host; ensure the embed still works under strict sandboxing (no parent-frame access, no third-party cookies).
- Bundle size. Embeds must load fast — lazy-load everything that is not needed for the initial render.
- Auth for private graphs inside an embed. The standard auth flow (redirect-based OAuth) does not work inside all iframes. Plan a token-based fallback.

## Notes for the implementer

Ship the iframe version first — it is universally compatible and requires less engineering. The script-tag version is a nice-to-have that can follow once the iframe proves the use case. Bundle size is the quiet success metric — a slow embed is worse than no embed.
