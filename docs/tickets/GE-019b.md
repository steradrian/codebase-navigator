# GE-019b — Migrate nodes to InstancedMesh + batched links

**Status:** TODO (deferred from GE-019)
**Phase:** Post-MVP scale (follow-up to GE-019)
**Effort:** L
**Depends on:** GE-019 (LOD label culling)
**Blocks:** —
**Trigger:** Graph exceeds ~500 nodes and render-loop profiling shows draw-call overhead dominating GPU time.

## Summary

Replace per-node `THREE.Mesh` allocations with a single `THREE.InstancedMesh`, and per-link `THREE.Line` allocations with a batched line geometry. Unlocks smooth rendering at 1000+ nodes by collapsing thousands of draw calls into one.

## Context

GE-019 shipped LOD label culling as the low-risk, immediately-visible piece. The instanced-rendering refactor was deferred because:

- `InstancedMesh` with `MeshBasicMaterial` does not support per-instance opacity. Every visual mode we ship today (selection dim, path highlight, blast-radius severity gradient, diff overlay, collapsed-cluster pulse) relies on `material.opacity` mutation per mesh.
- Implementing per-instance opacity requires a custom shader — substantial engineering that itself must be tested against the existing visual modes.
- MVP graph sizes (≤200 nodes) render fine today without it.

Ship this when a real workload exceeds 500 nodes.

## Scope

- Replace the for-loop-built `nodeMeshes: THREE.Mesh[]` with a single `THREE.InstancedMesh`. Per-instance attributes: position (via `instanceMatrix`), color (via `InstancedBufferAttribute`), and opacity (via a custom shader).
- Custom shader extends `MeshBasicMaterial` (or lives as a `ShaderMaterial`) to blend a per-instance opacity attribute.
- Replace `THREE.Line` per link with either:
  - A single `THREE.LineSegments` whose geometry carries all endpoints in one vertex buffer, OR
  - A custom shader with instanced quads (flat 2D lines in 3D space).
- Selection / path / blast / diff / collapsed-cluster visuals all continue to work — they read the same `expandedParents`, `blast`, `diffOverlayRef`, etc. refs, but now write to per-instance attribute arrays instead of per-mesh material properties.
- Sprite label pool: fix-size (~50 sprites), recycled based on which nodes are closest to the camera. Distant nodes get no label at all (beyond the LOD fade in GE-019).

## Out of scope

- GPU-based force simulation (that's GE-018b's successor, not this).
- Post-processing effects (bloom, SSAO).
- Replacing Three.js with a lower-level renderer.

## Acceptance criteria

- At 1000 nodes with simulation idle: stable 60fps.
- At 2000 nodes: interactive (30fps+).
- All visual modes produce indistinguishable output from the per-mesh version at small scale (verify against screenshots of the demo schema).
- No label texture leaks — verifiable via repeated schema reloads with stable GPU memory.
- Bundle size does not grow meaningfully (custom shader should be ~200 lines, not a new library).

## Risks

- Per-instance color + opacity attribute updates must be throttled. Uploading the full attribute buffer every frame when only a handful of instances changed is wasteful. Track a dirty flag.
- Visual regressions on the collapsed-cluster pulse, blast-radius severity gradient, and diff-overlay color coding are the highest-risk areas.
- Custom shader must preserve fog + depth behavior. Test against the existing fog setting in `GraphExplorer.tsx`.

## Notes for the implementer

Prototype the shader against a synthetic 1000-node graph first. Don't commit to the refactor direction until the visual fidelity passes a side-by-side screenshot check against the current renderer.
