# GE-009 — In-app schema editor UI

**Status:** DONE
**Phase:** Phase 1 — Foundation
**Effort:** M
**Depends on:** GE-003
**Blocks:** —

## Summary

A UI surface for creating, editing, and deleting nodes and links directly in the app, so non-developers can contribute to the graph without touching source files.

## Context

Today the only way to modify the graph is to edit `schema.js` and restart. That works for developers but excludes every non-technical contributor (PMs, designers, domain experts) from authoring. The Narrative Demo thesis depends on diverse contributors enriching the graph — ownership, descriptions, relationships are the kind of tacit knowledge that engineers do not always have.

This ticket is scoped conservatively — it is a structured editor, not a WYSIWYG graph editor. Users select a node or link, see its fields in a form, and edit. Creating new nodes and links is also form-based.

## Scope

An editor mode or panel accessible from the main UI that allows:

- Viewing a list of all nodes in the schema, filtered by type or group, with search.
- Selecting a node to edit its fields (name, description, type, group, owner, metadata). Changes write to the in-memory schema.
- Creating a new node, populating required fields, with type-appropriate defaults.
- Deleting a node (with a confirmation, and blocking if guided paths reference it — the user must remove it from paths first).
- The equivalent flows for links: list, edit, create, delete.
- Every creation or edit that touches schema sets `origin: "manual"` on the affected entity (or flags fields as manually overridden on auto entities, per the contract established in GE-007).
- Saving the schema persists changes into the in-memory working schema. Persistence to disk is handled elsewhere (GE-010 or GE-020).

The editor should respect the schema validator from GE-003 — invalid input is rejected inline with clear messages, and the user cannot save a malformed entity.

## Out of scope

- Guided path authoring — that is GE-015.
- Annotations (comments on nodes/links) — GE-023.
- Visual / drag-and-drop editing on the canvas (e.g., click-to-create link by dragging from one node to another). Defer to post-MVP.
- Bulk editing or multi-select.
- Undo / redo stack. Useful but non-trivial — file as a follow-up.
- Form schema auto-generation from types. Hand-write the forms — MVP does not need reflection.

## Acceptance criteria

- A user can create a new node with only the required fields, and it appears in the graph immediately.
- A user can edit any field of an existing node and see the change reflected.
- A user can delete a node; if it is referenced by a guided path, the delete is blocked with a clear message pointing to the blocking path(s).
- The equivalent flows work for links.
- Every manually created or edited entity is correctly tagged as manual (or has the appropriate field-level overrides flagged for auto entities).
- Malformed input is caught before save and surfaced inline.
- Navigation is keyboard-accessible.

## Risks

- Editing an auto-generated entity's field without flagging the override means the next OpenAPI re-import silently overwrites the user's change. This is a correctness bug. Verify the override flagging against the GE-007 merge engine's expectations before closing this ticket.
- The editor must not allow creating a link to a non-existent node — validation must fire before save, not after.
- Scope creep on this ticket is extreme. It is easy to grow into a full admin UI. Do not.

## Notes for the implementer

Err toward minimal and obvious. Two-column layout (list on left, form on right) is fine. No need for modals, wizards, or multi-step flows. The users for this feature are people who can read a form — they do not need a CMS.
