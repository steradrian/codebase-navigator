# GE-107 — Help panel + richer button tooltips

**Status:** DONE (core Tooltip component + Help panel shipped; wholesale title= migration proceeds incrementally)
**Phase:** UX / Discoverability
**Effort:** S
**Depends on:** —
**Blocks:** —

## Summary

Replace the native `title=` tooltips on top-bar buttons with styled custom tooltips that appear faster and carry more content. Add a `?` help button in the corner that opens a compact cheat sheet with keyboard shortcuts, button reference, and a "try this" demo walk-through.

## Context

User reports: "I have no clue what some buttons or features do." The existing `title=` attributes work but have ~1-2s browser delay before showing and can only hold one short line. For a power-user tool this is too little, too slow.

A full tutorial overlay gets skipped. A cheat sheet gets re-consulted.

## Scope

### Custom Tooltip component

- New `<Tooltip label={...}>{children}</Tooltip>` wrapper component.
- Shows a dark-themed styled tooltip on hover with ~200ms delay.
- Accepts multi-line content via a `label` prop (string or ReactNode).
- Auto-positions (above or below the target) to avoid clipping.
- Arrow pointer connecting to the target.
- Replace every `title=` attribute on top-bar buttons with this component.

### Content upgrade for tooltips

Each button's tooltip has three lines:
1. Short description ("Import OpenAPI specification")
2. Keyboard shortcut (if applicable) or "Click to open"
3. "When to use" clue ("Seed the graph from your backend spec")

### Help panel

- New `?` button in the TOP-RIGHT of the canvas (not top bar — corner overlay, doesn't consume header space).
- Keyboard shortcut: `?` or `h`.
- Opens a modal-style overlay with:
  - **Keyboard shortcuts** section — search, frame, paths, nav history, escape, help itself
  - **Mouse / trackpad** section — drag to orbit, shift-drag to pan, scroll to zoom, click to explore
  - **Buttons reference** — every top-bar and in-panel button in one list, with its description
  - **Try this** section — 4-6 numbered "demo moves" that walk the user through the most interesting features ("1. Import an OpenAPI spec. 2. Click a node and press ↓ Downstream blast. 3. Type 'show the auth flow' into Ask…")
  - **Version** footer — app version + link to the docs / backlog

## Out of scope

- Animated sequential tutorial overlay (skipped per discussion).
- Contextual help popovers that explain a feature when you first use it.
- Localization of tooltips / help content.

## Acceptance criteria

- Every top-bar button, when hovered, shows a styled tooltip within ~200ms.
- Tooltip content is 2-3 lines, readable, not clipped at viewport edges.
- `?` button visible at top-right corner.
- Pressing `?` or `h` (outside editable inputs) opens the help panel.
- Help panel's "Try this" section has at least 4 actionable steps.
- Panel closes on Escape or clicking outside.
- No layout shift — tooltips don't push content around.

## Risks

- Replacing every `title=` requires touching a lot of JSX. Keep the `<Tooltip>` component trivial to drop in so the diff is mechanical.
- Custom tooltips can feel janky if not positioned correctly. Flip-to-viewport logic must be robust.

## Notes for the implementer

Don't install a tooltip library — ~50 lines of inline code covers our needs. Positioning: calculate `getBoundingClientRect` on hover, decide above/below/left/right based on distance to each edge.

For the help panel, reuse the modal pattern from `ImportDialog` / `DiffDialog`. Keep it scrollable but no multi-tab complexity — one scrollable column is plenty.
