# GE-005 — Rename `source_meta` → `origin`

**Status:** DONE
**Phase:** Scaffolding
**Effort:** S
**Depends on:** GE-001
**Blocks:** GE-003, GE-006, GE-007

## Summary

The project design document proposes a `source_meta` field on links to track whether the link came from a human or an importer. The name collides semantically with `link.source` (the source node ID) and will confuse every reader. Rename to `origin` before the field ships anywhere load-bearing.

## Context

In the design document, the data model evolution section introduces `source_meta: "manual" | "auto:openapi"` on links. The proposed name was chosen to avoid clashing with the existing `source` field on links (which is the source node ID for the edge). `origin` is the better name — it carries the same meaning, reads naturally in English, and does not require mental disambiguation from `source`.

This is a cheap rename now and a painful one later once importers, merge engine, UI filters, and tests all reference the field.

## Scope

- Settle on `origin` as the canonical name across the entire schema (nodes, links, and any future annotations).
- Update the design document (`README.md` and any other docs referencing `source_meta`) to use `origin`.
- The schema type definitions in GE-003 will use `origin` — confirm alignment.
- No code uses `source_meta` today, so there is nothing to refactor in the codebase. This ticket is essentially a doc and type convention lock.

## Out of scope

- Introducing the `origin` field itself on the schema — that happens in GE-003.
- Any importer logic — GE-006 and GE-007.

## Acceptance criteria

- Zero references to `source_meta` remain anywhere in the repo (docs, comments, types, code).
- All references use `origin`.
- The GE-003 ticket and schema types agree on the name.

## Risks

- None significant. This is a cheap doc-level change landed before any real code depends on it.

## Notes for the implementer

Keep this ticket tight. If you discover the design doc uses `source_meta` in three places and `origin` in none, just change all three. If you find something more interesting mid-task, resist scope creep and file a follow-up.

## Resolution notes

Zero live-field references to `source_meta` ever existed — no code, no types, no schema adopted the name. Only the ticket's own paper trail (this file, the `BACKLOG.md` entry naming the ticket, and `GE-003.md` line 51 citing GE-005 as the rename dependency) references the string. Those are historical pointers, not usages, and are preserved so future readers can trace the decision. GE-003's types will be authored with `origin` from the start.
