# GE-010 — Export / import schema as JSON

**Status:** DONE
**Phase:** Phase 1 — Foundation
**Effort:** S
**Depends on:** GE-003
**Blocks:** —

## Summary

Save the current in-memory schema as a JSON file the user can download. Load a schema from a previously saved JSON file to replace the current in-memory schema.

## Context

Until server-side storage lands (GE-020), the only way to persist changes made in the app is to serialize them somewhere. JSON file download / upload is the cheapest, most obvious mechanism. It also makes sharing a graph between team members trivial — email, Slack, Git, whatever.

This is not a file format for long-term storage or team collaboration — it is a portable snapshot. Keep scope minimal.

## Scope

- An export action that serializes the current working schema to a JSON file and triggers a browser download. Filename should include the schema's `meta.name` and a timestamp.
- An import action that accepts a JSON file, validates it against the v1.0 schema validator from GE-003, and replaces the current working schema on success.
- Clear error messaging on validation failure, including the file name and the specific validation error.
- A confirmation dialog before the import overwrites unsaved changes.

## Out of scope

- Binary formats, compression, encryption.
- Partial import (merging a subset). If users want that behavior, they go through GE-008's import flow.
- Versioning, migration of older schema versions. If the file says v0.2, the validator rejects it — the user needs to import through an importer that targets v1.0.
- Cloud storage, shareable links (that is GE-022 / GE-020).

## Acceptance criteria

- Export produces a valid JSON file that, when re-imported, restores the graph identically.
- Import rejects malformed files with a helpful error pointing to the specific problem.
- Import warns before overwriting unsaved manual changes.
- The exported file is human-readable (pretty-printed, stable key ordering).

## Risks

- Stable key ordering matters for diff-friendliness — if the same graph exports differently on different runs, every git diff is noise. Sort keys consistently.
- Large schemas may produce large files. Not a concern at MVP scale.

## Notes for the implementer

Use the browser's `File` API — no external dependencies. This ticket should not introduce new packages.
