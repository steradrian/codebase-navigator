# GE-116 — Catalog curator (review dialog rewrite)

**Status:** TODO
**Phase:** UX
**Effort:** M
**Depends on:** GE-115 (catalog), GE-115b (propagation)
**Blocks:** —

## Summary

Replace the current "Review entities" modal — a flat scroll-list that asks the user to rename or merge 93 rows one at a time — with a catalog curator. Two tabs: **Catalog** (domains + their entities, counts, rename/merge/delete) and **Unclassified** (nodes that propagation didn't reach, with suggested assignments). Supports the two-level entity + domain model from GE-115.

## Context

The existing dialog was designed for open-vocabulary extraction (invent an entity per node, let the user clean up). That model is gone after GE-115. The new catalog is closed (derived from `components.schemas` + `tags`), so the user's job shifts from "clean up noise" to "curate the vocabulary" — small set, deliberate edits, with an escape valve for infrastructure files.

Concrete flows we need to support:
- Rename `bonus-issue` → `bonus` if the user considers them one concept.
- Merge `payment-provider` into `payment`.
- Delete a catalog entry that shouldn't be there (e.g. a leaky value object the filter missed).
- Add a catalog entry manually (for a domain object the spec doesn't expose — internal DB table we'll add later via GE-117).
- Inspect Unclassified nodes and optionally assign them to an existing catalog entry.

## Scope

### Layout

Modal, same position as the current one, sized ~720px wide. Two tabs:

1. **Catalog (N)** — N = number of catalog entities
2. **Unclassified (M)** — M = count of nodes with no entity AND not `isHub` (hubs are expected to stay unclassified; we surface the non-hub unclassified separately)

Tab order: Catalog first (primary curation flow), Unclassified second.

### Catalog tab

Hierarchical list grouped by **domain**. Each domain header shows the domain name + node count. Under each domain, list entities belonging to it (an entity is "in" a domain if >50% of its tagged nodes carry that domain).

Entity row: `● <color dot>  <entity name>  [<node count>]  [edit] [merge] [delete]`

Click edit → inline rename input. On commit, run `renameEntity(schema, from, to)` (already exists).

Click merge → prompt for target entity (dropdown of other catalog entries). On commit, run `mergeEntity`.

Click delete → confirm modal. On commit, unset `entity` on every node tagged with this value; remove from `meta.entities`. Nodes become Unclassified. Document in the dialog: "This doesn't delete the nodes — it just untags them."

Domain header: `[rename] [delete]` — domains can be renamed or deleted too. Deleting a domain unsets `domain` on every member node but doesn't touch their entity.

At the bottom of the Catalog tab: `+ Add entity` button. Opens a small form: name, domain (dropdown), description (optional). On commit, adds to `meta.entities` and `meta.domains` (if new). The entity starts with 0 tagged nodes — the user assigns nodes via the Unclassified tab or direct edit.

### Unclassified tab

List of nodes with no `entity` (and not `isHub`). Each row:

```
<node type icon>  <node name>  <node path/description>   [assign ▼]
```

`[assign ▼]` opens a dropdown of catalog entities + a "Skip (leave unclassified)" option. On commit, sets `entity` AND `manualOverrides: [..., 'entity']` on the node so propagation won't overwrite.

Above the list: a search bar to filter by name. A "Bulk assign" button that becomes active when 2+ nodes are selected via checkbox — assigns the chosen entity to all selected.

### Footer

- **Re-tag nodes** button — calls `propagateEntities(schema)` and refreshes both tabs. Useful after the user adds a catalog entry or deletes one.
- **Save dictionary** (already exists, same behavior — commits the catalog to `schema.meta`).
- **Cancel** — discards edits.

### Preserving user intent

- Manual overrides (`manualOverrides: ['entity']`) persist across propagation, imports, re-renames (unless the entity itself is renamed, in which case the override updates to the new name).
- If the user deletes an entity from the catalog, nodes with manual overrides pointing at it lose both the entity AND the override. Warn in the confirm modal.

### Entity banner on the graph surface

Keep the existing "N entities discovered" banner that currently appears after GE-103 extraction. Post-GE-115 it means "N entities detected from the OpenAPI spec." Tweaks:
- Show count of Unclassified non-hub nodes alongside: `15 entities · 47 unclassified nodes — Review`.
- Banner auto-dismisses once the user has opened the dialog (regardless of whether they saved — acknowledging is enough).

## Out of scope

- Bulk assign via keyword match ("find all filenames containing 'payment', assign to payment"). Power feature for later.
- Showing entity relationships (entity A contains entity B) — entities are flat in this model.
- Undo across modal sessions. Edits commit to schema immediately once saved.
- Multi-select + drag-to-merge between catalog entries. Merge stays as a per-entity action.

## Acceptance criteria

- Open the dialog after importing the admin-dashboard spec. Catalog tab shows 6 domains and ~15 entities arranged under them, with correct counts.
- Rename `bonus-issue` to `bonus`. Every node tagged `bonus-issue` now carries `bonus`. `bonus-issue` is removed from `meta.entities`.
- Delete `tag` from catalog (it's an artifact of the UI-Tag schema). Nodes that were tagged `tag` lose their entity, move to Unclassified.
- Unclassified tab shows the non-hub unclassified nodes. Hubs (`isHub: true` after GE-115b) do not appear here — they live in their own conceptual bucket.
- Assign an Unclassified node to `payment`. It disappears from the Unclassified tab and increments `payment`'s count in the Catalog tab.
- Hit "Re-tag nodes" after making catalog changes. Propagation runs, Unclassified count updates to reflect the new catalog state.
- Manual assignment survives a subsequent OpenAPI re-import.

## Risks

- Domain-vs-entity confusion in the UI. Users might edit a domain header expecting to change the entity name. Keep the visual hierarchy unambiguous: domain headers are muted/uppercase, entity rows are standard case with color dots.
- Deleting a catalog entry is destructive (untags nodes). The confirm modal must be clear. Count the affected nodes in the confirm.
- Re-propagation on every small edit would feel slow. Don't auto-propagate — require the explicit "Re-tag nodes" button. Propagation on a 10k-node graph finishes in <100ms typically, but not worth doing per-keystroke.
- URL state (GE-022): if the catalog changes while a shared link pinned a specific entity, the old entity might not exist. Load path for URL state should handle missing entity gracefully (fall back to no-filter).

## Notes for the implementer

The existing `EntityReviewDialog.tsx` is the starting point. Split into:
- `EntityReviewDialog.tsx` — shell, tabs, footer
- `CatalogTab.tsx` — domain-grouped list, edit/merge/delete per entity, add-entity form
- `UnclassifiedTab.tsx` — node list, assign dropdown, bulk assign
- `useCatalogCounts.ts` — memoized `{ entities: Map<string, number>, domains: Map<string, { total: number, entities: string[] }> }`

Keep all schema mutations in existing pure helpers (`renameEntity`, `mergeEntity` — extend with `deleteEntity`, `addEntity`, `renameDomain`, `deleteDomain`, `assignEntityToNode`). Each testable in isolation.

The "assign" dropdown in Unclassified should group options by domain for scannability — same structure as the Catalog tab.
