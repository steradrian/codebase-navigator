# GE-111 — Entity-grouped peers in the connection panel

**Status:** TODO
**Phase:** UX
**Effort:** S
**Depends on:** GE-105 (section-based panel), GE-103 (entity field), GE-114 (backfill on load)
**Blocks:** —

## Summary

In the INFO panel's connection sections (GE-105), when the selected node has 15+ peers or touches 4+ distinct entities, sub-group the rows inside each section by entity. A one-line sub-header per entity with a count pill. Applies to hubs especially (utils, index, client files) where the current flat list is a wall.

## Context

Evidence from `Ann test` (615 nodes / 1759 links): 29 hub nodes with degree ≥20, top hub at 76, median hub touching 9 distinct entities, max 16. Today the connection sections (Imported by / Imports / API calls out / …) list peers flat — the user sees 40 `Imported by` rows with no way to tell at a glance which domain they belong to.

Grouping by entity inside the section turns "40 rows" into "Payment (8) · Bonus (6) · Auth (4) · Dashboard (12) …" — a scannable directory. Clicking an entity sub-header collapses/expands it.

## Scope

- Inside each `ConnectionSection` from GE-105, if:
  - the section has >=10 rows, OR
  - the section's peers span >=4 distinct entities
  - then render entity sub-groups. Otherwise keep the flat list.
- Sub-group header: colored dot (entity color) + entity name + `[N]` count. Clickable to collapse/expand. Default expanded.
- Rows within a sub-group keep the two-line layout from GE-105.
- Peers with no entity roll up under an "Unclassified" sub-group, shown last.
- Sub-group order: by count descending, ties by entity name. "Unclassified" always last.
- No sub-grouping when color-by-entity is off AND the selected node itself has no entity (stay flat — grouping would feel arbitrary).

## Out of scope

- Sub-grouping by type within a section. Sections already ARE type/semantic buckets.
- Saving expand/collapse state across sessions.
- Sub-grouping in the annotation or path sections.

## Acceptance criteria

- Select `utils` (76 peers in `Ann test`) — each connection section with >=10 rows shows entity sub-groups with correct counts.
- Select a leaf node (3 peers, 1 entity) — no sub-groups, flat list as before.
- Collapsing a sub-group hides its rows and updates the header count is not required (count stays, just the rows collapse).
- Entity sub-group colors match the legend/palette used in color-by-entity mode.

## Risks

- If GE-114 hasn't shipped, sub-grouping will fall through to "Unclassified" on existing stored graphs. Hard dependency — GE-111 should not merge before GE-114.
- Visual density in the panel. The sub-header has to feel like a divider, not a row, or users will mis-click it as a peer.

## Notes for the implementer

Extend the `groupConnections` helper from GE-105 to produce a two-level structure: `Section → EntitySubGroup → Row[]`. Keep the flat-vs-grouped decision inside the helper (pure function, testable). Render the same `ConnectionRow` inside sub-groups — don't duplicate row logic.
