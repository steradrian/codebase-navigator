# GE-015 — Guided path authoring UI

**Status:** DONE
**Phase:** Phase 2 — Intelligence
**Effort:** M
**Depends on:** GE-003
**Blocks:** —

## Summary

A UI mode where users construct a guided path by clicking nodes in sequence, typing an annotation at each step, picking a path color, and saving the result into the schema.

## Context

This is the feature that makes Graph Explorer different from every other graph visualizer. Paths turn a structural diagram into a narrative — onboarding walkthroughs, incident replays, user journey demos, architecture explanations. Until users can author paths without hand-editing `schema.js`, the feature is locked behind a technical barrier that excludes the exact users (PMs, TPMs, architects, support engineers) who benefit most from it.

## Scope

A path authoring mode, enterable from the paths panel or a dedicated button:

- Click a node to add it as the current step. The panel shows a growing ordered list with each step, its node name, and an editable annotation field.
- Reorder steps via drag-and-drop in the panel.
- Remove a step from the panel.
- Edit the annotation inline — plain text, multi-line, no formatting (keep it simple).
- Preview the path in real time — as steps are added, the graph dims and highlights per the usual path visualization. The author sees exactly what the reader will see.
- Edit path metadata: name, description, color (color picker from a small palette), category (from a fixed list of categories: `user_journey`, `data_flow`, `incident`, `onboarding`, `other`).
- Save adds the path to the schema's `paths` array. Cancel discards changes.
- Editing an existing path enters the same mode pre-populated.
- Deleting a path (from the path list, with confirmation).

## Out of scope

- Branching paths (a step with multiple next-step options). Linear only for MVP.
- Conditional annotations ("if user role is X, skip this step"). Linear only for MVP.
- AI-suggested annotations based on the underlying nodes. File as a follow-up — low effort but depends on GE-017's AI integration landing first.
- Collaborative authoring (multiple users editing the same path). Post-MVP.
- Path templates. Post-MVP.

## Acceptance criteria

- A user can create a path by clicking a sequence of nodes, typing annotations, and saving.
- The new path appears in the paths list and works with the existing guided path viewer.
- Editing an existing path preserves all prior steps and annotations and allows free modification.
- Paths can be reordered, edited, and deleted.
- Keyboard navigation works throughout.
- The live preview shows the path exactly as a viewer would see it.

## Risks

- Click-to-add conflicts with the existing "click node to select" behavior. The authoring mode must gate or override selection — make the mode visually obvious (cursor change, border on viewport, mode indicator).
- Annotations may grow large. The panel must handle multi-line text without breaking layout.
- Losing unsaved work is painful. Warn on navigation-away if there are unsaved changes.

## Notes for the implementer

This is the marquee Phase 2 feature. The UX must feel effortless — a PM writing their first path is the test. If it takes them more than 60 seconds to create a three-step path from nothing, the feature fails its purpose. Prototype against a real use case (a real system, a real user journey) before closing.
