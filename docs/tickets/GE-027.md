# GE-027 — Figma component tree import

**Status:** TODO
**Phase:** Phase 4 — Ecosystem
**Effort:** M
**Depends on:** GE-003, GE-007
**Blocks:** —

## Summary

Pull a Figma file's component hierarchy via the Figma API and translate it into graph nodes and links representing the design system structure. Connect these to existing UI nodes from the codebase parser for a full design-to-code mapping.

## Context

Designers and engineers rarely share a single mental model of the product. Designers think in components and variants; engineers think in files and imports. The Figma import provides a bridge — each Figma component becomes a graph node that can be linked to its code implementation (via the codebase parser), making the design-implementation gap visible.

This is a lower-priority ticket than most of Phase 4 but a strong wedge for design-tooling positioning.

## Scope

- Authenticated access to a target Figma file via a personal access token or OAuth.
- Traverse the Figma file's node tree, extracting components, component sets, and variants.
- Emit nodes (Figma-component type) and links (variant-of, contains, uses) reflecting the hierarchy.
- When a Figma component's name matches a code component's name (from GE-026), optionally create a link between them — labeled "implemented by" or similar.
- Every node and link carries `origin: "auto:figma"`.
- Configuration: Figma file URL / key, auth token, name-matching rules for code linking.

## Out of scope

- Full Figma design fidelity (colors, spacing, tokens). Only the component tree structure.
- Real-time sync with Figma (updates as designers work). One-shot imports, triggered manually or via CI (GE-025).
- Design token import. Post-MVP.
- Support for non-Figma tools (Sketch, Penpot). Figma only.

## Acceptance criteria

- Given a valid Figma file and token, the importer produces a schema containing the file's components and variants as nodes.
- Variant relationships are correctly represented as links.
- Name-matching to code components (when the codebase parser has run) produces the expected cross-links.
- Re-running is deterministic (IDs are stable).
- API errors (auth, rate limit, missing file) surface clearly without crashing.

## Risks

- Figma API rate limits. Large files with thousands of components require paginated fetches and backoff.
- Name-matching is heuristic — designers and engineers rarely agree on naming. Expect many false negatives. Offer manual link-matching in the UI as a follow-up.
- Figma's API model has quirks (node types, detached instances). Document what is supported and what is skipped.

## Notes for the implementer

Keep this ticket scoped tight — component tree only. Designers who want design-token or color mapping can file follow-up tickets; do not over-build on the first pass.
