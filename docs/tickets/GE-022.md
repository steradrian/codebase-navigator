# GE-022 — Shareable deep links

**Status:** DONE
**Phase:** Phase 3 — Scale
**Effort:** S
**Depends on:** GE-003
**Blocks:** —

## Summary

Encode the current view state (selected node, active guided path + step, camera position, visible mode flags) into the URL so that copying and sharing the URL lands the recipient on the same view.

## Context

Deep links are the single most undervalued feature in this backlog. They make demos sharable, let team members link each other directly to "this specific thing," and turn every ad-hoc Slack message into a repeatable reference. The doc filed them under Phase 3 as an infrastructure feature. They are actually a Phase-2-or-earlier UX feature — trivial to implement and disproportionately valuable.

This ticket is small and has no blockers other than schema stability.

## Scope

- Define a URL state encoding covering:
  - Selected node ID (if any).
  - Active guided path ID + current step index (if any).
  - Camera state (theta, phi, radius, target offset).
  - Mode flags (2D/3D, blast-radius on/off + direction, pinned cluster expansions).
- On any state change worth sharing, update the URL with `history.replaceState` (no new history entries on camera nudges — use `pushState` only for meaningful actions like selecting a node or starting a path).
- On page load, parse the URL and restore state. Graceful handling of malformed URLs — fall back to default view with a console warning.
- A "copy link" button that copies the current URL to the clipboard with a confirmation toast.

## Out of scope

- Server-side URL shortening. Use the real URL, however long it gets.
- Encoding the full schema in the URL (for teams without a backend). Deferred — when graphs become large, the URL becomes unwieldy anyway.
- History / undo navigation via browser back/forward. Nice-to-have but out of MVP scope.
- Permission-aware share links (requires auth). Post-MVP, relates to GE-020.

## Acceptance criteria

- Selecting a node updates the URL; pasting the URL into a new tab lands on the same node.
- Activating a guided path and stepping through updates the URL; sharing the URL lands a recipient at the same step.
- Camera state round-trips through the URL.
- Mode flags round-trip.
- The copy-link button works and provides visible feedback.
- Malformed or partial URLs do not crash the app.

## Risks

- Frequent `replaceState` calls during camera orbit can be noisy. Throttle camera state updates — only write to URL every ~500ms while the camera is moving.
- URL length. If state grows, consider compact encoding (base64 + compression) — but for MVP, readable query params are fine.
- Cross-origin concerns — if the app is ever embedded (GE-030), deep links must still work inside the embed frame.

## Notes for the implementer

This is a small, high-leverage ticket. Do not overthink the encoding. Query parameters are readable and debuggable; compression can come later.
